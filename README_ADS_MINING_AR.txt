تحديث Easy GRAM لمطابقة طريقة إعلانات SLY

1) ارفع ملفات هذا المشروع واستبدل النسخة المنشورة.
2) في Supabase الخاص بـ Easy GRAM فقط، شغّل الملف EasyGram_SLY_AdsMining_AllInOne.sql كاملاً.
3) راجع نتيجة التحقق في نهاية SQL؛ يجب أن تظهر دوال تأكيد الإعلان وبدء التعدين واستلام التعدين.
4) من Admin > Settings ضع معرّف Reward / Action INT النشط المخصص لتطبيق Easy GRAM. لا تستخدم معرّف SLY؛ القيم الافتراضية في الكود ليست ضماناً أنها فعّالة لحسابك.
5) أعد تشغيل الخدمة، ثم أغلق Mini App وافتحه مجدداً من بوت Easy GRAM.

السبب المهم: SQL الخاص بمهمة 6 ساعات وحده لا ينشئ دوال التعدين المرتبطة بالإعلان. الملف AllInOne يجمع ترحيل الإعلان والتعدين ومهمة 6 ساعات في عملية واحدة.

تشخيص الجلسة من جدول easygram_ad_sessions:
- لا يوجد صف جديد: begin لم يُسجل.
- confirmed_at فارغ: إعلان لم يبدأ/لم يكتمل أو فشل تأكيده.
- confirmed_at موجود وused_at فارغ: الإعلان تأكد لكن خطوة المهمة/التعدين لم تستهلك الجلسة.
- used_at موجود: الجلسة استُهلكت؛ راجع easygram_mining_sessions أو رصيد easygram_users.

التحقق المنفذ هنا: فحص صياغة ملفات JavaScript باستخدام node --check. تعذر إكمال npm build بسبب تبعيات npm غير المكتملة في بيئة الفحص، ولم تتوفر بيانات Supabase أو AdsGram الحقيقية لاختبار الإعلان الفعلي.
